# Environments

Three environments run the same code and the same container images. Every
difference between them is deliberate and listed here; where each one is set is in
the last column.

| | **dev** (local) | **staging** | **production** | Set in |
|---|---|---|---|---|
| Purpose | Development on the owner's VM | Pre-release testing; test data only | The public site and survey | — |
| Runs on | Docker Compose on the admin machine | DigitalOcean droplet `itv-staging-1` (`blr1`, 2 GB) | DigitalOcean droplet `itv-prod-1` (`blr1`, 2 GB) | `infra/terraform/{staging,production}/main.tf` → `modules/droplet` |
| Website | http://localhost:8080 | https://staging.indiantaxpayervoice.org | https://indiantaxpayervoice.org (`www` redirects) | `infra/terraform/cloudflare/variables.tf` (`environments`) |
| Survey | http://localhost:8081 | https://survey-staging.indiantaxpayervoice.org | https://survey.indiantaxpayervoice.org | same |
| LimeSurvey admin | http://localhost:8083 (open) | https://survey-admin-staging.indiantaxpayervoice.org (Cloudflare Access) | https://survey-admin.indiantaxpayervoice.org (Cloudflare Access) | same |
| Statistics | http://localhost:8082 | https://stats-staging.indiantaxpayervoice.org | https://stats.indiantaxpayervoice.org | same |
| **Survey open to the public** | yes | **yes** (testing) | **no — controlled release** | `infra/env/<env>.env` (`ITV_SURVEY_OPEN`) |
| Search engines | not indexed | not indexed (`noindex` everywhere) | website indexed; survey, admin and statistics hosts `noindex` | `ITV_ENV` → `wordpress/bootstrap.sh` and the Caddyfile `robots_*` snippets |
| Bot check (gate) | off (`ITV_GATE_ENABLED=0`) | on | on | `.env`; refused off outside dev |
| Statistics refresh | every 5 min | hourly | hourly | `.env` (dev) / `infra/env/<env>.env` |
| Rounding, minimum group | 5, 20 | 5, 20 | 5, 20 | `infra/env/<env>.env` |
| Databases | MariaDB containers | MariaDB on the host | MariaDB on the host | `COMPOSE_PROFILES` in `.env` |
| HTTPS | none (plain HTTP; optional local TLS on :8443) | Cloudflare Full (strict) + Origin CA, Caddy | same as staging | `compose.staging.yaml`, `infra/staging/Caddyfile.origin-ca` |
| Admin access | open locally | Cloudflare Access (email code), re-verified at the origin | same as staging | `infra/terraform/cloudflare/access.tf` |
| Public access | open locally | **private**: every staging host needs Cloudflare Access (email code); CI uses a service token | public | `infra/terraform/cloudflare/access.tf` (`private` in `environments`) |
| Articles | drafts via `wp_article.sh` | every article as a draft, refreshed on each deploy; publishing here is the review step (changed text goes back to draft) | only articles published on staging with the same text, via the approved "Publish article" workflow | `research/articles/`, `docs/ci-cd.md` |
| WAF, rate limiting, cache rules | none | Cloudflare (zone-wide rules include its hosts) | same as staging | `infra/terraform/cloudflare/{waf,main}.tf` |
| Images | built locally | built by CI on every merge to `main` | **promoted**: the same images staging ran, never rebuilt | `.github/workflows/ci.yml` |
| Deploys | `docker compose up -d` | automatic on merge to `main` | manual "Run workflow" → owner approval (GitHub environment `production`) | `.github/workflows/ci.yml` |
| CI deploy key | — | own key, restricted to sync and deploy | own key, restricted to sync and deploy | `~/.config/itv/ci-deploy-key[-production].pub`, GitHub secrets |
| Secrets | generated by `init-local-env.sh` | generated on the droplet, never leave it | generated on the droplet, never leave it | `/opt/itv/.env` (mode 600) |
| Backups | none | daily, encrypted, 14 days + 30-day copy | daily, encrypted, 14 days + 30-day copy | `infra/staging/backup-db.sh`, cron |
| Questionnaire change on deploy | replace by hand | survey replaced automatically (test responses deleted) | **deploy refuses** (needs a planned migration) | `infra/staging/remote-deploy.sh` |

## Changing a setting

- **Non-secret, per-environment settings** (`ITV_SURVEY_OPEN`, refresh interval,
  rounding, minimum group): edit `infra/env/<env>.env` in a pull request. The next
  deploy of that environment applies them; only `ITV_*` names that do not look like
  secrets are accepted.
- **Hostnames, Access, WAF, caching:** `infra/terraform/cloudflare` (`environments`
  map), applied from the admin machine after review.
- **Server size and firewall:** the environment's `infra/terraform/<env>/main.tf`.

## Opening the production survey (controlled release)

1. Pull request: set `ITV_SURVEY_OPEN=1` in `infra/env/production.env`.
2. Merge (staging deploys and is smoke-tested), then **Actions → CI → Run workflow**,
   environment `production`, and approve the deployment.
3. The production smoke tests confirm the gate shows the bot check instead of
   "not open yet". Closing it again is the same with `0`.
